# BudStacks template builder

A skill for [Claude Code](https://claude.ai/claude-code) and claude.ai that builds storefront templates for the BudStacks cannabis SaaS platform, on Template Design System v2.

A template is data, not code: four files and an assets folder that tell the platform which sections to show, with what content, in what style. The skill composes them from the platform's fixed section library and checks the result against the platform's own contract before it is uploaded.

```
{slug}/
  layout.json            nav, sections and footer, with content and options
  defaults.json          design system and page content
  styles.css             a few lines of scoped CSS, often none
  template.config.json   name, slug, marketplace description
  assets/                images, logos, video
```

## Install

```bash
git clone https://github.com/Gerard161-Site/budstack-template-skill.git
cd budstack-template-skill
./install.sh
```

That copies the skill to `~/.claude/skills/create-budstacks-template/`. In the BudStacks workspace it is already available: `templates/.claude/skills/create-budstacks-template` is a symlink to this repository.

Needs Node 20 or later for the validator. Nothing else is installed.

## Using it

Ask for a template and give it one of three things:

| You have | Say |
|---|---|
| A design handoff from a designer or a design tool | "Build this template" and attach the handoff |
| Only the brand | "Create a template for Meadow Clinic, a UK medical cannabis clinic" |
| A Figma file | "Create a template from this Figma: https://www.figma.com/design/…" |

**If someone else is designing first**, give them `references/design-brief.md` before they start. It says what the platform can render, what the designer decides, and what to hand back. A design made without it will ask for things the section library does not have.

The skill then: agrees the design system and the section plan with you, writes the files, validates them, and walks you through upload and a review of the live preview at phone, tablet and desktop widths.

## Validating a template yourself

```bash
node scripts/validate-template.mjs path/to/template-folder
```

Errors are things the platform would ignore or render badly: an unknown section or config key, a design-system key the runtime does not read, a missing image or font, unreadable text, CSS that fights the platform. A template with errors must not be uploaded. Warnings are quality-rubric items for a reviewer to decide (`references/quality-rubric.md`).

The validator's own tests: `node --test scripts/`.

## Keeping it in step with the platform

`references/contract/` is generated by the platform from the code that renders templates: every section, every config key, the design-system schema. The skill and the validator read nothing else, so they cannot describe sections or tokens that do not exist.

When `budstack-saas` changes its sections or design tokens:

```bash
scripts/sync-contract.sh /path/to/budstack-saas
node --test scripts/
```

Then commit the updated `references/contract/`.

## The claude.ai copy

claude.ai keeps its own uploaded copy of this skill and does not follow this repository. After any change here, re-upload the folder in claude.ai (Settings → Capabilities → Skills), or that copy will keep building templates the old way.

## Repository layout

```
SKILL.md                       the workflow the model follows
references/
  design-brief.md              give this to whoever designs the template
  quality-rubric.md            what a finished template is reviewed against
  contract/                    generated by the platform — do not edit by hand
  design-tokens.md             what each design token does in the browser
  layout-archetypes.md         starting patterns for the section order
  color-theory.md, typography.md
  copy-style-cannabis.md       tone and compliance for copy
  page-content.md              About page and fixed-page content
  assets-pipeline.md           image, logo and video preparation
  accessibility-checklist.md
  editor-parity.md             how emitted keys appear in the Store Editor
  figma-import.md              the Figma input path
scripts/
  validate-template.mjs        the validator (plain Node, no install)
  validate-template.test.mjs   its tests
  lib/                         the checks
  sync-contract.sh             refresh references/contract/ from budstack-saas
install.sh
```
